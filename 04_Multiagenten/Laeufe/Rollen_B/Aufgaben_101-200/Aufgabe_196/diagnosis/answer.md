The fault is concentrated in [assistantUpsellConfig.ts](/app/packages/components/hooks/assistant/assistantUpsellConfig.ts:30). Both paid builders require an addon name and add it directly to `planIDs`. Its duplicate resolver falls back to the Mail Plus addon for an unsupported plan, so either paid flow can select the wrong addon.

The shared resolver already exists in [helpers.ts](/app/packages/components/payments/core/subscription/helpers.ts:3) and returns `undefined` when a plan has no match. The fix should use it in both paid paths, seed `planIDs` with the current plan or selected plan, and add an addon only when the resolver returns one. [payments/core/index.ts](/app/packages/components/payments/core/index.ts:1) must export the resolver and `SelectedPlan`; the assistant files and [ProtonPlanCustomizer.tsx](/app/packages/components/containers/payments/planCustomizer/ProtonPlanCustomizer.tsx:5) currently import `SelectedPlan` through an internal path.

The [existing upsell tests](/app/packages/components/hooks/assistant/assistantUpsellConfig.test.ts:1) cover known plans but do not cover an unsupported plan or absent addon. No project source or tests were changed; this run was limited to fault localization.
