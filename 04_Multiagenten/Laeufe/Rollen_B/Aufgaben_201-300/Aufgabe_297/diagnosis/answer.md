The double login occurs because this checkout has no reverse proxy authentication path. [Configuration](/app/conf/configuration.go) has neither proxy setting; [serveIndex](/app/server/app/serve_index.go:20) sends no authentication payload; and [authProvider](/app/ui/src/authProvider.js:7) initializes a session only after password login.

The fix belongs in those files and [auth.go](/app/server/app/auth.go:28): validate the configured header against the *actual peer address*, create a missing user on first trusted login, update `LastLoginAt`, issue a token, and send the complete auth payload only after successful authentication. [server.go](/app/server/server.go:57) applies `RealIP` before app routing, so forwarded headers need particular care at the whitelist boundary. [redactrus.go](/app/log/redactrus.go:33) also needs map and nested value redaction before the config payload can safely be logged.

There is one requirement ambiguity: it says the header user must already exist, then says to create that user on first login. I read the latter as the intended trusted first login behavior.
