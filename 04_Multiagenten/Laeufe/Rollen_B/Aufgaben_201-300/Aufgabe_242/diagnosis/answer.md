I found the cause in [VoiceBroadcastPlayback.ts](/app/src/voice-broadcast/models/VoiceBroadcastPlayback.ts:323). `updateLiveness()` uses playback state and the current chunk as well as info state, so a Started or Resumed broadcast can appear grey while playback is stopped, paused, or buffering. `setState()`, `skipTo()`, and first-chunk handling can also change liveness independently of `setInfoState()`.

The fix should put the requested mapping in `determineVoiceBroadcastLiveness.ts` and have `setInfoState()` alone apply it through `setLiveness()`. The existing `setLiveness()` guard already prevents duplicate change events. Invalid incoming info states are currently ignored, so whether those events should reset liveness remains an ambiguity; the utility itself should return `not-live` for unknown or undefined input.
