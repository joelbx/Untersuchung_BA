The likely fault is in [detector/wordpress.go](/app/detector/wordpress.go:37). `WpCveInfo` has no fields for `description`, `poc`, `introduced_in`, or `cvss`, so JSON decoding discards them. [extractToVulnInfos](/app/detector/wordpress.go:182) then leaves the record’s summary, severity metrics, and optional metadata unset.

The same function already carries over the `wpscan` source, URLs in input order, `vuln_type`, and `fixed_in`. It also creates a record for **every** `references.cve` value, while the requirement specifies the first. Timestamps are copied without explicit UTC normalization. [convertToVinfos](/app/detector/wordpress.go:165) processes every top-level version key, which could mix versions if a payload contains more than one.

A fix should cover enriched and null or absent fields, including an empty optional map. The repository has no Enterprise payload fixture, so the exact `cvss` JSON shape remains uncertain.
