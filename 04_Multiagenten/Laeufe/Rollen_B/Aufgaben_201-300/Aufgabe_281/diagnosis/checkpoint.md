Fault-localization diagnosis (2026-10-21)
- Both requested APIs are absent from src/database/mongo/hash.js and src/database/redis/hash.js. Existing incrObjectFieldBy handles only one field; Mongo uses $inc/upsert, Redis uses HINCRBY.
- Mongo setObjectBulk demonstrates tuple input, unordered bulk, and cache.del(keys). A per-key $inc document via upsert/updateOne would give atomic multi-field updates; Mongo rejects nonnumeric existing fields without partial changes to that document. An unordered bulk allows other keys to proceed, but bulk errors can represent partial success, so cache invalidation must account for successful keys.
- Redis batch/pipeline of HINCRBY commands is not per-key atomic. ioredis batch is aliased to pipeline in src/database/redis/connection.js; helpers.execBatch throws on first command error after execution. An atomic per-key server-side operation (e.g. Lua validation then HINCRBY) is needed, and results must be tracked per key before cache eviction.
- Input must be validated completely before writes: array of [string key, plain increment map] tuples, each delta Number.isSafeInteger, normalized field names, blocked dangerous names. Mongo helpers.fieldToString converts dots to fullwidth, so reject forbidden names before normalization (or check both forms). Empty array must return before accessing client/cache.
- Existing tests in test/database/hash.js cover incrObjectFieldBy and setObjectBulk, but no incrObjectFieldByBulk cases. No project source or tests changed; no tests run.
