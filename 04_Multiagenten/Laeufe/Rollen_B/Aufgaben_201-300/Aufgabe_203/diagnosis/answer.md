I located the accessibility gaps, but did not edit project source or tests: this run is constrained to fault localization.

- [ShareDialog.tsx](/app/src/components/views/dialogs/ShareDialog.tsx:229) renders the room link with the raw URL as its text and no descriptive label. A localized `aria-label` such as “Link to room” would give it a clear announced purpose. The string belongs in [en_EN.json](/app/src/i18n/strings/en_EN.json:2699). The link’s click handler also prevents navigation and selects the URL; that behavior should be considered when verifying the fix.
- [ProfileSettings.tsx](/app/src/components/views/settings/ProfileSettings.tsx:164) renders two links to the hosting URL. The second contains only an image with empty alt text, leaving that link unnamed. One reusable `ExternalLink` around the translated “Upgrade” text should replace both anchors and provide an accessible new-tab cue.
- The new component belongs in `src/components/views/elements/ExternalLink.tsx`. Its style partial belongs under `res/css/views/elements/` and should be imported from [_components.scss](/app/res/css/_components.scss:130). Existing image spacing in [_ProfileSettings.scss](/app/res/css/views/settings/_ProfileSettings.scss:47) would then be obsolete.

Other external anchors occur across the settings tabs and shared settings components. The requirement’s “all external links in the settings view” scope likely includes those; in-app action anchors should be excluded. I found no existing tests for these specific components.
