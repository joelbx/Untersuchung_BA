The upgrade failure starts in [install_collections](/app/lib/ansible/galaxy/collection/__init__.py:402): it returns early when an installed collection satisfies the requested constraint, so it never checks for a newer allowed version. When resolution does run, [CollectionDependencyProvider](/app/lib/ansible/galaxy/dependency_resolution/providers.py:36) prioritizes installed candidates, including dependencies. The [CLI install options](/app/lib/ansible/cli/galaxy.py:365) have no `--upgrade` or `-U` flag to change that behavior.

A fix should pass the flag through the CLI and [resolver construction](/app/lib/ansible/galaxy/dependency_resolution/__init__.py:31), select the newest candidate that satisfies all constraints, replace installed dependencies only when required, and skip installation when the resolved version is already present. It should cover `--no-deps`, opt-in `--pre`, conflicts, and requirements-file installs. One uncertainty is how `--no-deps` should report an existing dependency that violates a new constraint, since the current resolver omits dependency checks in that mode.
