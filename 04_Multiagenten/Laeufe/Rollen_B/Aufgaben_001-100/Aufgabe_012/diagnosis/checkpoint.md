Diagnosis: WebEngine RequestInterceptor.interceptRequest computes is_xhr but calls shared.custom_headers(url=url) without an XHR-specific fallback flag, then applies Accept-Language with setHttpHeader. shared.custom_headers always reads content.headers.accept_language using global fallback and adds the encoded value, overriding JavaScript's header. Config.get(name, url=url, fallback=False) returns usertypes.UNSET when no URL-specific rule matches; String.to_py preserves that sentinel. A fix should add fallback_accept_language=True to custom_headers, query with fallback=False only when the argument is False and a URL exists, omit Accept-Language when the result is usertypes.UNSET, and pass fallback_accept_language=not is_xhr in the WebEngine interceptor. Explicit per-domain values should still apply; normal requests and url=None retain current behavior. Existing tests/unit/browser/test_shared.py covers only url=None; tests/unit/browser/webengine/test_webengineinterceptor.py has no interceptRequest header coverage. WebKit createRequest uses the default call and should retain behavior. No project source or tests changed.
