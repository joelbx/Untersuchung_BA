The repeated requests originate in [`fetchLink`](/app/applications/drive/src/app/store/_links/useLink.ts:30). It awaits the API request without retaining a failed result. The existing [debounce helper](/app/applications/drive/src/app/store/_utils/useDebouncedFunction.ts:46) removes its cached promise when that request fails, so the next attempt calls the API again. `getEncryptedLink`, `getLink`, and `loadFreshLink` all reach `fetchLink`.

The fix belongs in the outer `useLink` wrapper: cache only errors with `NOT_FOUND`, `NOT_ALLOWED`, or `INVALID_ID` for the affected `(shareId, linkId)`; reject later attempts with that error until the backoff expires; then permit a retry. Other links, other errors, and successful fetches should continue normally. The key needs to distinguish pairs whose plain concatenation could collide.
