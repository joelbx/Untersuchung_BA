# Fault localization progress

Inspection complete. No project source or tests changed.

- Global property schema: `db/migration/20200130083147_create_schema.go` defines `property(id, value)` only. A new migration under `db/migration/` should create `user_props(user_id, key, value)` with a composite unique/primary key, and consider migration of existing `LastFMSessionKey_<uid>` rows.
- `model/properties.go` defines only global `PropertyRepository`; `model/datastore.go` has only `Property(ctx)`. `persistence/property_repository.go` implements global reads and writes. Add user scoped interface, constructor in `persistence/user_props_repository.go`, and `SQLStore.UserProps` in `persistence/persistence.go`. All SQL predicates must include both user_id and key. `persistence/sql_base_repository.go:userId(ctx)` and `model/request/request.go:UserFrom` show existing context pattern; missing user currently maps to `-1`.
- `core/agents/lastfm/auth_router.go:sessionKeys` manually concatenates `LastFMSessionKey_` and uid for Put/Get/Delete. Its callback route is outside the authenticator group, so `fetchSessionKey` must attach the callback uid to context (ideally after validating/loading the user) before `UserProps(ctx)` writes. Authenticated `/link` routes already have a contextual user. `core/agents/lastfm/agent.go` passes uid but scrobbler flows have a contextual user.
- `tests/mock_persistence.go` must implement the new DataStore method when changes are made. Existing `core/agents/lastfm/agent_test.go` seeds a prefixed global property and would need adjustment; `persistence/property_repository_test.go` is the closest repository test pattern. Check cross-user isolation, upsert, get-missing, delete, missing-user context, migration preservation.
- `auth_router.go:fetchSessionKey` logs save failure without ctx; `server/middlewares.go` puts requestId in logger context. Callback error already displays `middleware.GetReqID(ctx)`. Pass ctx to the log call and include request ID where available; avoid logging session key/token.
- Ancillary concern: `persistence/property_repository.go:Put` swallows update errors (`if err != nil { return nil }`); a new repository should not copy that behavior.
