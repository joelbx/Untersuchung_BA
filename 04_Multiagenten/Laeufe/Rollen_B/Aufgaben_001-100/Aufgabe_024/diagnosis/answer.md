The likely fault is in [load_book.py](/app/openlibrary/catalog/add_book/load_book.py:138). `find_author` stops at the first nonempty name query before `find_entity` checks dates, and its surname query compares full date strings. That can prevent a valid fallback match between authors whose dates share years but use different formats. Input `*` characters also reach wildcard queries unescaped.

[remove_author_honorifics](/app/openlibrary/catalog/add_book/load_book.py:222) takes a dictionary instead of a string, matches prefixes without a word boundary, and can turn an honorific-only name into an empty name. New-author creation copies only selected fields. [extract_year](/app/openlibrary/core/helpers.py:330) already extracts the first four-digit run, but matching does not use it.

The fix should check extracted birth and death years at each match stage, attempt surname matching only with both valid input years, treat input asterisks literally, and preserve all fields when creating an author.
