# Payment token verification refactor checkpoint

Status: investigating existing token creation, modal flow, and call sites. Assigned systematic-debugging process in use.

Tooling: `rg` is unavailable (`/bin/bash: rg: command not found`); using local `find` and `grep`.

Root cause: `createPaymentToken` owns `PaymentVerificationModal` construction and accepts `createModal`, so verification cannot be injected. It routes every nonchargeable initial status into the UI. `process` recursively waits on uncancellable timers, so abort leaves outstanding polling and timing depends on wall-clock delay. Working reference: `usePayPal.tsx` constructs `PaymentVerificationModal` with `onProcess` and an `AbortController`.

Hypothesis: extracting the existing modal wiring into `getDefaultVerifyPayment` and binding it through `getCreatePaymentToken` allows callers to reuse verification. Explicit status branching prevents failed initial tokens from entering the modal. Focused tests added for chargeable, pending, and failed initial statuses; running before fix.

Implementation: extracted `VerifyPayment`, `getDefaultVerifyPayment`, and `getCreatePaymentToken`; migrated six call sites (including `single-signup/Step1.tsx`, found by account type checking). `createPaymentToken` now bypasses verification for chargeable status, delegates pending status, and rejects initial failure statuses. Polling uses cancellable timers and returns a chargeable boolean; modal and PayPal consumer submit only on true. Added focused helper and modal tests.

Verification so far: focused helper suite passed (12 tests), components TypeScript check passed. A broader components Jest run had two CreditsModal tests failing because they expect `PaymentMethodID` in the buy-credit payload, although the preexisting chargeable-token path returns only `toTokenPaymentMethod(Token)`; inspection of HEAD confirms this mismatch predates the patch. The same run found a modal test regression from a mock AbortController without `signal`; fixed with optional signal access and rerunning. Account TypeScript check found the additional Step1 caller; migrated it and rerunning.
